# Project Structure — E2E-автоматизація AirGuard

## Дерево проєкту

```text
airguard_hil/                          # Корінь тестового проєкту (Test Controller side)
│
├── conftest.py                         # Фікстури pytest: device (session, VID-пошук порту),
│                                       #   hil (керування реле/DAC через агент), mqtt_listener
│                                       #   (paho-mqtt + Queue), clean_device (function scope:
│                                       #   сброс конфігу + power cycle + wait boot)
│
├── pytest.ini                          # testpaths=tests, addopts=-v --tb=short,
│                                       #   markers: smoke / functional / e2e / stability / slow
│
├── requirements.txt                    # pyserial, pytest, paho-mqtt, pyfirmata (агент), matplotlib
│
├── drivers/                            # Вся робота з залізом
│   ├── __init__.py
│   ├── device_driver.py                # DeviceDriver: CLI over UART (115200 8N1), find_port по VID/PID,
│   │                                   #   send_command, read_lines, wait_for_pattern, status()
│   │                                   #   → dict, config get/set/save, get free_heap / version / alarm
│   ├── hil_agent.py                    # HILAgent: power_cycle() (реле живлення через Arduino),
│   │                                   #   set_dac(mV) (signal injection на аналоговий вхід MQ-135),
│   │                                   #   read_gpio() (перевірка стану LED/buzzer)
│   ├── mqtt_listener.py                # MqttListener: connect/subscribe test/#, Queue повідомлень,
│   │                                   #   get(timeout), history для evidence, publish (імітація cloud-команд)
│   └── ota_helper.py                   # Локальний HTTP-сервер для OTA-образу + контроль прогресу
│
├── tests/
│   ├── __init__.py
│   │
│   ├── smoke/                          # Смоук тести - швидкі перевірки працездатності
│   │   ├── test_smoke.py               # test_boot_time (NFR-001), test_version_in_boot_log (FR-003),
│   │                                   # test_status_alive (FR-003), test_help_lists_commands (FR-003)
│   │
│   ├── functional/                     # Функціональні тести (один тест = одна вимога з PRD)
│   │   ├── test_sensor.py              # FR-001: діапазон/точність CO2, реакція на DAC-ін'єкцію;
│   │                                   # FR-002: температура/вологість SHT31 (встановлюємо значення
│   │                                   # через signal injection / симуляцію I2C)
│   │   ├── test_config.py              # FR-004: set/get/save + restore після reboot;
│   │                                   # FR-005: валідація меж і невідомих ключів;
│   │                                   # FR-006: factory_reset
│   │   ├── test_alarm.py               # FR-007: тривога при CO2 > порогу (LED/buzzer/status);
│   │                                   # FR-008: гістерезис скидання; FR-009: калібрування
│   │   ├── test_mqtt.py                # FR-010: WiFi-стан у status; FR-011: схема payload,
│   │                                   # топік з конфігу; FR-012: реконект після рестарту брокера
│   │
│   ├── e2e/                            # End-to-End: повний ланцюжок «фізика → cloud-повідомлення»
│   │   ├── test_co2_to_mqtt.py          # CS-3: DAC 1500 ppm → перехоплення payload → assert co2_ppm,
│   │                                   #   alarm, fw, device_id (ланки 1–6, Lesson 12)
│   │   ├── test_alarm_e2e.py           # CS-1: ін'єкція 1500 ppm → LED+buzzer (read_gpio агента)
│   │                                   #   + alarm=triggered у payload
│   │   └── test_ota.py                 # CS-4 / FR-013: OTA з локального сервера → нова версія
│   │                                   #   в boot-лог + конфіг збережено
│   │
│   ├── stability/                      # Нефункціональні тести (nightly, без CI-таймауту)
│   │   ├── test_memory_leak.py         # NFR-004: 8 год, free_heap кожні 5 хв, допуск 5 КБ,
│   │                                   # графік heap_trend.png у reports/
│   │   ├── test_config_race.py         # NFR-005: 1000 циклів «config set + rapid power cycle»
│   │   ├── test_power_cycle.py         # NFR-007: 1000 power cycle, конфіг і reset reason на місці
│   │   ├── test_mqtt_latency.py        # NFR-002: ін'єкція → таймстемп → payload у підписника ≤ 2 с
│   │   └── test_cli_latency.py         # NFR-003: час відповіді CLI-команд ≤ 500 мс
│
├── tools/
│   ├── find_port.py                    # Ручний пошук COM-порту по VID/PID (для дебагу стенда)
│   ├── plot_heap.py                    # Побудова графіка heap для reports/
│   └── ota_server.py                   # Запуск HTTP-сервера з OTA-образом вручну
│
├── reports/                            # Evidence: pytest-логи, payload-и MQTT,
│                                       # скріншоти, traceability-звіти по прогону
│
├── docs/
│   ├── PRD.md                          # Копія PRD (джерело вимог для трасованості)
│   ├── stand_diagram.png               # Схема стенда
│   └── traceability_matrix.md          # Матриця «Вимога → Тест»
│
└── README.md                           # Докладний рідмі
```
